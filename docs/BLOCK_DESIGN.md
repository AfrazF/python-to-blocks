Source tags: `(user)` = confirmed by the repo owner from a real screenshot; `(pybricks-svg)` = extracted from a Pybricks block SVG; `(ours)` = our own choice, not from Pybricks; `(derived)` = computed by the ×0.85 (field fill) or ×0.75 (stroke) rule.

**Field fill** is the pill fill only — block × 0.85. Square dropdowns and square fields are not darker; they use `fill="transparent"`. See `docs/FIELD_DESIGN.md` for the full rules.

- Workspace background `#ecf0f1`.
- No icons in v1 (user decision).
- **Guiding principle:** follow SPIKE Prime's color conventions. Where Pybricks Code already uses a color for a construct, keep it — e.g. setup and `straight` share the same blue.
- **Deviations from Pybricks:**
  - The `set up` hat is orange (`#ffbf00`) to match SPIKE Prime's "when program starts" hat. Tasks and other async constructs are purple.
  - `async def` definitions render as purple task blocks; `await <async-call>` renders as a purple `await` wrapper around a pink call block.
  - The `hub` setup block is **Output blue** (`#4c97ff`), like the motor and drive-base setup blocks. It does **not** join the Hardware objects row.
  - Plain `def` functions are pink (like Scratch custom blocks), not yellow. Deliberately distinct from tasks.
  - Object chips are **cyan** (`#46BAEC`) for hardware that moves the robot (Motor, DriveBase). Not pink, to keep pink from being overloaded.
  - `if` uses Flow orange (`#ffab19`), matching wait/repeat. No separate decisions color.
  - `print` is Python-functions purple, not Output blue — it is a Python builtin, not a robot action.
  - `hub.display.*` and `hub.light.*` get their own **SPIKE Prime purple** (`#9b6af6`, border `#691ff0`) rather than Output blue, so hub output reads as distinct from robot motion. These are SPIKE Prime's own values, not derived.
- **Known code/doc mismatch (fixed in v2d.1):** the Hardware objects cyan (`#46BAEC`) is defined in `src/theme.ts` but never rendered. Object chips are `pybricks_var_reporter` blocks whose `jsonInit` hardcodes `#ff6680`, and `src/pybricks.css` forces `.pybricks_var_reporter > .blocklyPath { fill: #ff6680 }`. Until v2d.1 lands, chips render pink.

## Rules

- Each file's top-level code sits under one yellow **`set up`** hat (user decision).
- **Await:** hidden on Pybricks' own blue/orange blocks (verified: they add it when generating). For calls Pybricks cannot express (e.g. `await home(...)`), show a separate **`await`** wrapper block holding a value-shaped call block (user decision). Pybricks' pink call blocks add no await (verified).
- `async def` is a **task** block, plain `def` is a **function** block, same yellow shape (user decision). Parameters show as pink chips.
- Omitted defaults show as Pybricks does: e.g. `then hold` is shown even when `then` is not written (verified).
- Do not show `await wait(0)` (Pybricks adds it, your code does not have it).
- Keyword arguments in generic call blocks show as `name: value` labels (our default).
- `Direction.CLOCKWISE` / `COUNTERCLOCKWISE` show as words, since there are no icons (our default).
- Comments become Blockly comments on the next block (user decision). Comments with no next block: OPEN.
